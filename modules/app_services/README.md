# app_services

App-composition services: the cross-cutting session/config state and the DI
register modules that assemble each feature's data layer over the shared client.

This package sits **above** the feature modules and below the shell. It exists
because these services need to see several features at once (session state feeds
auth, config feeds animal editing), which no single feature may do.

## Exports

- **`AuthService`** — session: login, token refresh, the current shelter and
  role. The rest of the app reads the session from here.
- **`ConfigService`** — server-driven catalogs (animal attributes, type/status
  dictionaries), cached per shelter.
- **`AnimalService`** — composition over several features' data for the animal
  detail/edit screens.
- **`DebugService`** — `isDevFlavor` and the debug-screen hook. The prod
  implementation is inert; the dev flavor overrides it.
- **`DeepLinkService`**, **`FileService`**, **`PreferenceStorage`**,
  **`ThemeStorage`**, document export / share platform surface.
- **`src/service/client/*_register.dart`** — per-feature injectable modules that
  build data sources and repositories over the shared ports.
- **`app_services_di.dart`** — the `AppServicesPackageModule` that `base/di`
  pulls in.

## Regenerating

`app_services_di.module.dart` is generated by injectable — never edit it by hand.
After changing an annotated class or a register module, run from the repo root:

```sh
fvm dart run build_runner build --delete-conflicting-outputs
```
